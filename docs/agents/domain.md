# Documentação de domínio

## Leitura

Antes de explorar uma área, leia `GLOSSARY.md` na raiz e os ADRs
pertinentes em `docs/adr/`.

O projeto usa contexto único, compartilhado por pipeline e site.
Se um documento não existir, prossiga sem exigir sua criação.

## Vocabulário

Use os termos do glossário ao nomear conceitos em issues,
propostas, código e testes. Respeite as traduções estabelecidas.
Lacunas podem ser tratadas pela skill domain-modeling.

## Decisões

Se uma proposta contrariar um ADR, explicite o conflito.
Em divergência, vale o ADR mais recente.
